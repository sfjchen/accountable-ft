# runs

Run outputs land here (gitignored except this file). A fixed external simulator (gemini-3.5-flash-lite, thinking off, on Vertex) predicts the model's decision after each bank edit from the policy, the model's frozen account and the edit. The primary endpoint is ΔSim (`sim_delta` = `sim_acct` - `sim_shuf`): its accuracy with the case's own account minus with another case's account under the same policy, so only case-specific content counts. `sim_gross` (`sim_acct` - `sim_noacc`, own account vs the decision alone) is reported beside it. V (`self_V`), the same with-minus-without difference for the model predicting itself, is secondary.

Setup, once per shell: `export PATH=/opt/homebrew/share/google-cloud-sdk/bin:$PATH` (ADC for Vertex) and `F=(--backend gemini --vertex --model gemini-3.5-flash-lite --temperature 0)` (a zsh array, so `$F` splits into flags).

- Bank, once per data file: `python infer.py --mode bank --data data/smoke.jsonl` writes `data/smoke.bank.jsonl` and `data/smoke.bank.meta.json` (mix, sources, drops) on the primary population (slice unseen_family_train_vocab, view prose).
- Answer run, always with `--bank` so the bank's edited cases get fresh decisions: `python infer.py --data data/smoke.jsonl --bank data/smoke.bank.jsonl $F --slice unseen_family_train_vocab --view prose --out runs/pilot.jsonl` (add `--cases 13` for a stratified subset).
- Simulator, one command for all 3 passes on the frozen run: `python infer.py --mode simulate --all-sim --data data/smoke.jsonl --bank data/smoke.bank.jsonl --frozen runs/pilot.jsonl $F` writes `runs/pilot.simulate.jsonl` (own account), `runs/pilot.simulate_shuf.jsonl` (`--shuffle-accounts`: the item's own Decision line with the Policy support and Assumptions lines of another case's frozen answer under the same policy; rows carry `shuf_src`, `shuf_partner` and `shuf_decision_match`, and items with no partner are skipped and counted in `shuf_missing` in the meta) and `runs/pilot.simulate_noacc.jsonl` (`--no-account`). evaluate refuses a shuf file from before Nov 7 (no `shuf_src` "frozen" or `shuf_decision_match`): rerun `--all-sim`. For a trained model only the answer run changes. The simulator and its decoding stay fixed across every run compared.
- Local checkpoints (vllm or a vLLM server): name each run `<cond>-e<epoch>[-s<seed>]` and pass `--cache-tag` with the same name, since the model path can point at new weights and the cache would otherwise return the old answers.
- Self-prediction (secondary): `--mode predict` with the model under test, into `runs/pilot.predict.jsonl` and with `--no-account` into `runs/pilot.predict_noacc.jsonl`.
- Score: `python evaluate.py runs/pilot.jsonl --data data/smoke.jsonl --bank data/smoke.bank.jsonl --json runs/pilot.eval.json --render`. Answer the rendered `runs/pilot.edits.jsonl` with the same model into `runs/pilot.answers.jsonl` and rerun evaluate with `--data data/smoke.jsonl runs/pilot.edits.jsonl` for the boundary and necessity metrics. sim metrics are scored on the bank items present in all 3 simulate files, beside the baselines `sim_const_unchanged` (always the frozen base decision) and `sim_oracle` (the engine label), with `sim_delta[changed]` and `sim_delta[unchanged]` split by whether the fresh decision moved. A bank item without a fresh decision stops evaluate: rerun the answer run with `--bank`.
- Checkpoint selection: `--epoch K` takes every condition (and seed) at the same fixed epoch K, fixed before any account metric is read. `--select-by sim_delta --select-control <ctrl-run>` adds the best-of-k pick as a table labelled EXPLORATORY, never the reported pick. Seed aggregates (`<cond>-s<k>`) are per group, printed for the primary population and all.
- Each run writes `<run>.jsonl` and `<run>.meta.json` (tokens, wall time, cost estimate). evaluate picks up `<run>.{repeat,answers,predict,predict_noacc,simulate,simulate_noacc,simulate_shuf}.jsonl` and writes `<run>.interventions.jsonl`. `cache.jsonl` holds every response, so reruns are free.
